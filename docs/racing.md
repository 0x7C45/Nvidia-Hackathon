# FLY CIRCUIT 赛车实验场

赛车的身体接口以 [Body API v1](body-api.md) 为唯一契约入口。后续车辆能力、感觉输入、动作输出、奖励和学习模式的扩展先核对该文档与 `/openapi.json`，再修改游戏适配层。本文描述游戏，不新增另一套身体协议。

## 启动与操作

在项目根目录运行：

```sh
npm --prefix web run build
./flybrain race
```

打开 <http://127.0.0.1:8787/race/>。`race` 与 `web` 使用同一个服务；已有服务时无需启动第二个进程。原神经观察室继续在 `/`。

- 选择 2、3 或 4 果蝇，可额外加入 1 辆传统机械赛车手。比赛为 1、3 或 5 圈，每场最多 180 个模拟秒。
- 点击「开始比赛」时自动连接随车脑观察。右侧独立脑视图保留完整 166,700 个神经元、原来的脑区颜色及 114 个官方外形，可拖动旋转、滚轮缩放、切换头部／躯干部、只看激活、点选细胞、按需加载完整骨架与全屏观看。
- 选择排行榜赛车手，右侧相机与随车脑观察切换到该车；切换脑观察会新建 session 并重置神经状态。主视图可切换总览、跟车和驾驶视角，支持拖动旋转、缩放和点选赛车。
- 随车观察在后台异步运行，赛车无需等待神经计算。收起脑视图或点击「停止随车观察」可停止观察计算。使用「原生驾驶实验」时大脑实际驾驶车辆，严格等待真实神经运算；此时收起视图只停止显示，不会停止控制。
- 把选中赛车的控制方式设为「我来驾驶」，使用 WASD／方向键、Shift 氮气、Space 漂移，也可使用画面上的触屏按钮。同一时刻只有一辆手动车。
- 「开始奖励训练」在独立 Worker 中训练 24 代、120 代或持续训练。可以暂停、导出、导入驾驶记忆；「应用到比赛」装载新策略并重新发车。已在进行的比赛不自动换权重。
- 页面切到后台会暂停比赛与训练，释放本页面拥有的原生大脑；回到页面后由用户继续比赛。界面暂停后按需绘制。

## 控制与观察来源

| 控制来源 | 决策依据 | 更新什么 | 并发限制 |
| --- | --- | --- | --- |
| 传统机械赛车手 | 曲率前馈、车道／朝向反馈、超车规则 | 无学习 | 可多车 |
| 神经控制网络 | 道路与身体传感器输入，11→18→5 tanh MLP | 独立赛车网络的 311 个参数 | 每车独立实例，可多车 |
| 原生 MaleCNS | 本车 64×32 真实 WebGL 画面，`visual_bci` 动作读出 | `frozen`，脑内权重更新数为 0 | Body API v1 独占 1 辆 |
| 随车脑观察 | 同一车的真实相机、身体与行为反馈；原驾驶控制器保持运行 | 完整 MaleCNS 真实放电，`frozen` | 同时观察 1 辆，可切换 |

神经控制网络不是 166,700 个神经元 MaleCNS 的副本。其输入为车道偏移、运动朝向、速度、当前与前方两个距离的曲率、氮气、前车距离与横向差、离道状态、车道偏好，共 11 维；输出转向、油门、刹车、氮气、漂移。这个版本的外部驾驶网络使用工程传感器，不是从像素端到端学习。完整 MaleCNS 接收真实相机像素、显式声明的身体感觉输入，以及正向行为奖励后的糖刺激，显示自身的实际神经响应。

## 画面与物理

Three.js 使用项目已有依赖，不引入远程模型、外部字体或 CDN。赛车用一个 WebGL2 上下文的 viewport/scissor 绘制赛道与车载视野；树木、灯柱、道路虚线和轮胎痕迹采用实例绘制。赛车像素比限制为 1.5，只有可见车载视野或实际原生输入需要时读回 64×32 小纹理。右侧独立滚动区域有裁剪，离屏镜头不绘制。

脑视图为独立可复用的 `BrainMonitor`，复用原有 `BrainView`。其像素比上限 1.25，拖动时跟随浏览器刷新，不再人为限到 30 FPS；完整神经点云一次绘制，114 个官方外形仍合并成 3 批网格，共 4 次基础绘制调用。新活动和镜头操作触发绘制，暂停且镜头静止时不重绘。收起、滚出可见区域或隐藏页面时暂停脑显示并关闭其 WebSocket，不创建第二个原生脑实例。

翠野环线长度由同一份等弧长中心线计算，约 495 米、路宽 14 米。画面、模拟、训练与地图共用 `track.ts`。车辆采用街机风格的自行车模型：纵向加速与阻力、转向、横向偏移、漂移侧滑与抓地力损失、氮气消耗／恢复、路外减速、护栏和车车碰撞。车体在漂移时相对运动方向偏转并留下轮胎痕迹。

普通比赛（包括开启随车观察）以 1/60 秒持续更新，神经请求不阻塞世界。每次神经观察仍推进 100 ms，但采样时刻与神经时间独立，界面显示采样赛时和数据年龄。只保留一个正在处理的神经请求，空闲后采集最新图像，不积压旧画面；氮气／触碰短脉冲及奖励会保留。原生驾驶实验保留 100 ms 严格锁步，每个物理子步不超过 20 ms。

右侧画面使用 FOV 90°、宽高比 2 的车载第一视角。输入原生大脑的纹理使用同一相机姿态、FOV、场景和宽高比，隐藏自己的车模避免遮挡。视觉取样和缩略图都通过 WebGL2 的异步像素缓冲与 fence 读回，不在每帧同步等待 GPU。主视图直接跟随 `requestAnimationFrame`，移除了会误丢正常刷新帧的 61 FPS 阈值。

随车观察会跟随选中的赛车重新建立会话，界面明确显示当前来源。原生驾驶模式中，选中另一辆车只改变车载镜头，Body API 控制的赛车保持不变，脑视图仍显示实际受控赛车的大脑。

## Body API 的驾驶与观察边界

适配层为 `web/src/race/body.ts`，复用 `sdk/flybody.mjs`：

1. 查询 `/api/v1/body/capabilities`，要求 `protocol_version=1.0`。
2. 从 `/neurons` 按官方类型解析 `SNpp30` 左／右、`SApp10`、`SNta13` 的稳定 ID，声明 `body_left`、`body_right`、`nitro`、`touch` 四个感觉通道，各使用 30 mV gain。创建 session：`preset=visual_bci`、`learning_mode=frozen`、`record_observations=true`，然后 `reset(seed=71, reset_learning=false)`。映射查询失败不会使用虚构的 ID。
3. 从绑定赛车渲染 64×32 RGBA。`visionFromRGBA(..., {flipY:true})` 翻转 WebGL 行方向并将 sRGB 转为线性亮度，连同实际速度、左右运动反馈、正在生效的氮气、触碰和上一步正向行为奖励对应的 `sugar` 输入提交 `step(..., {dt_ms:100})`。细节以 [Body API 赛车接入](body-api.md#本项目赛车接入) 为准。
4. 原生驾驶模式中，`turn` 直接映射归一化转向；正 `forward` 为油门，负值为刹车。`forward>0.8 && abs(turn)<0.1` 请求氮气；`abs(turn)>0.35 && forward>0.2` 请求漂移，再由物理可用条件决定是否实际触发。没有隐藏的机械驾驶辅助或最低油门。随车观察模式保留原赛车动作，原生读出不接管车辆。
5. 原生驾驶用返回的动作推进世界 100 ms 再发送 reward。异步观察不调用世界推进，世界持续按自己的时钟运行；神经步骤结束时，取从上次已确认位置至今的奖励分量差额并发送。提交过程中新增的奖励留到下一次，避免丢失或重发。
6. 原生驾驶在绑定车辆完成时结束；随车观察等到所有车辆完成。到 180 模拟秒仍未完成则截断。最后一步如有行为奖励，先完成额外一个 100 ms 的显式糖刺激窗口，再提交结束标记；异步观察不会改变已结束的游戏时间。释放前等待已开始的 step/reward 配对完成。观察连接失败只停止观察，赛车继续运行；原生驾驶连接失败则停止实验。

每个异步图像输入带 `observation.context`：`clock=sampled`、`source_time_ms`、`source_interval_start_ms`、`source_id=car_N`。它记录图像的世界时间与短暂感觉信号的来源区间，仅作为 journal 元数据，不参与神经计算。浏览器另外保留每步的采样赛时、反馈截至赛时、神经时间与往返耗时；这些数据随比赛记录导出。

所有写请求携带 `X-Flybrain-Local: 1`，生产网页与接口同源。原生观测、动作与回执写入现有 `experiments/body/{session_id}.jsonl`；页面提供该 session 的下载链接。刷新或非正常关闭时，本页面只使用自己保存在 `sessionStorage` 的 session ID 恢复／释放所有权，不抢占其他身体控制器。

页面关闭时额外提交 keepalive 释放请求，避免原生大脑被已关闭的页面长期占用。强制关闭发生在请求中途时，最后一步可能没有完成奖励配对；journal 保留实际收到的事件，不补造奖励。

## 奖励规则

| 分量 | 数值 | 结算条件 |
| --- | --- | --- |
| `progress` | 每米 +0.055 | 在赛道内沿正确方向前进；路外前进不给分，反向产生负分 |
| `overtake` | +8 | 由落后变为领先超过 4 米，无碰撞、未离道、速度超过 10 m/s；同一对车 8 秒冷却，起跑前 2 秒不计 |
| `nitro` | +1.5 | 同一氮气段实际前进超过 18 米，速度超过 33 m/s，在曲率较低的路段；该段只结算一次 |
| `corner` | +3 | 完成一个曲率超过 0.019/m、长度超过 10 米的弯道，保持正向、未碰撞／离道，出弯超过 12 m/s |
| `drift` | +2 | 在上述有效过弯中实际侧滑角超过 0.12 rad 的漂移距离超过 9 米 |
| `lap` | +20 | 正向累计距离到达新一圈，反复跨越同一圈线不重复发奖 |
| `collision` | −5 | 撞车或撞护栏；0.8 秒冷却 |
| `offtrack` | 每秒 −1.2 | 车中心横向偏移超过 6.3 米 |

氮气和漂移按键本身没有奖励，停车不能刷分。所有分量包含在比赛记录；原生模式将本步分量总和交给 Body API。奖励结构的后续变更应同步本表、游戏实现与测试。

## 训练、记忆和结果含义

初始策略通过 65,000 条传统机械车手示范学习基础驾驶；随后执行 12 代仅按实际模拟回合奖励选择的 `(1+12)` 神经进化。每个候选评估 3 个不同起点、各 38 模拟秒，保留优于当前策略的参数。训练过程中策略推理不调用机械车手；机械车手只作为对手。网页训练继续这一奖励优化过程，在独立模拟回合运行，不直接拿观看中那场比赛当作在线梯度更新。

记忆保存在 `localStorage`，可导出 JSON 后跨会话恢复。导入校验结构、参数维度、数值、种子与评估记录。清除浏览器数据会删除浏览器保存的记忆，项目提供的基础权重仍在 `web/public/race/baseline.json`。训练曲线显示真实评估值。

当前验证使用额外起点种子 `[101,211,307]`；平均 38 秒行驶距离从 1,191.68 米提高到 1,278.08 米，平均奖励从 158.04 提高到 176.29，三个验证回合均无碰撞和路外行驶。序列化后重载的评估完全一致。具体结果及生成脚本在 `reports/racing-training.json` 和 `scripts/train_racing.mjs`。这些结果只说明这个赛道上的外部控制网络得到改善，不代表 MaleCNS 学会赛车，也不保证未知赛道泛化。

比赛导出包含本场实际装载的权重、最新待应用权重、种子、配置、每 200 ms 的车辆状态与动作、奖励事件、带两个时钟的观察记录，以及原生 journal 链接。单场最多 180 秒，页面保留最近 12 场比赛档案；需要长期保留时导出。原生 JSONL journal 持续由服务保存。

## 后续原生学习路线

原生连接组可塑性仍需按 [Body API 的奖励与可塑性章节](body-api.md#奖励与可塑性) 实现：

1. 在 `scripts/body_plasticity.py` 实现并显式注册经过数值验证的学习规则。保持图拓扑和固定基线可恢复，报告真实 `weight_updates`，明确 `reset_learning` 语义。
2. 训练输出要有可持久化的脑内权重与学习痕迹；需要新增接口时先更新协议与 MD，不能把浏览器控制网络检查点当作脑内记忆。
3. 使用相同相机与奖励比较冻结模型、学习模型、关闭奖励模型；记录训练前后表现、独立起点、跨会话记忆保持与完整图权重变化。
4. 多原生果蝇比赛需要在 Body API 契约中明确多实例或状态切换，以及每只果蝇的独立 episode、神经状态与资源预算。当前 v1 的单实例约束不能通过多个浏览器并发 session 绕开。
