# Fruit fly brain experiment

## Project facts

- Phase one is local, full retained MaleCNS v1.0 fixed-weight neural simulation.
- Upstream code is `vendor/doomfly`, pinned to `71ecf53d78eaffaf1a57ed7b0ccf5d458abc9f33`.
- Preserve upstream source; local launch and measurement code belongs in `scripts/`.
- The working graph must contain 166700 neurons, 25582938 directed edges, and 124177617 synaptic contacts. Weak edges, self edges, and isolated annotated neurons remain present.
- Inputs come directly from the official MaleCNS bucket using the pinned source manifest. Raw segmentation objects remain in the complete source files; the importer accounts for excluded non-neuronal and unresolved objects.
- `./flybrain prepare` downloads, verifies, imports and compiles. `./flybrain smoke` runs controlled stimuli. `./flybrain benchmark --wall-seconds 600` runs the full graph for ten minutes of wall time.
- Runtime: project `.venv`, Python 3.11, native C++ LIF kernel, 0.1 ms neural timestep, 10 ms observation interval, one BLAS thread, learning disabled.
- `reports/` contains actual measurements. Refer to JSON/CSV evidence when describing resource usage or success; estimates and upstream results do not establish local performance.
- The local web viewer lives in `web/` and `scripts/web_server.py`, served by `./flybrain web` at `http://127.0.0.1:8787`. The user explicitly requested local construction rather than Sites.
- `web-data/` holds 166700 actual neuron locations: 139662 soma, 976 to-soma and 26062 official skeleton anchors. An anchor is not an inferred soma. All 114 official neuropil surfaces are retained with display-only mesh simplification.
- WebSocket packets contain the real count of every neuron in a 100 ms simulated-time window. The stream has been compared cell-by-cell with a fresh native model; see `reports/web-signal-validation-v2.json`. FLY2 losslessly encodes active indices and counts, with implicit zeros and a dense fallback.
- The viewer uses one shared native simulation and pauses computation without visible viewing clients. Hidden tabs disconnect; the renderer draws on demand and batches the 114 retained neuropil surfaces into three region meshes. Performance evidence is in `reports/runtime-optimization.json` and `reports/render-idle-validation.json`. Neural graph and dynamics remain the fixed baseline.
- The racing game is FLY CIRCUIT at `/race/`, launched with `./flybrain race` (same server as `web`). It uses `web/race/` and `web/src/race/`, the existing Three.js dependency, local WebGL2, one renderer for track and selected driver's POV, and the existing Body API SDK. The racing integration is documented in `docs/racing.md`, subordinate to `docs/body-api.md`.
- Racing supports 2/3/4 independent small neural-policy drivers plus an optional conventional driver and manual control. These policies are external 11-18-5 MLP controllers, not copies of the MaleCNS graph. Driving-school imitation and subsequent reward-based evolution are measured in `reports/racing-training.json`; browser checkpoints persist locally and can be exported. Native MaleCNS can control exactly one car with real 64×32 camera input and 100 ms lockstep physics. Multiple native brains and biological synaptic learning are not implemented.
- Biological plasticity training and public deployment are subsequent work. Upstream deployment instructions refer to its separate public Doom website, not this local experiment.
- The local embodied bridge is Body API v1 under `/api/v1/body`: HTTP JSON with generated OpenAPI, lockstep `reset → step → reward → release`, stable MaleCNS body IDs, optional vision/retina/sensor input, normalized readouts and JSONL journals. The browser/Node and Python clients are in `sdk/`; the integration contract is `docs/body-api.md` and examples are in `examples/`.
- Body API v1 currently exposes only `learning_mode=frozen`: rewards are recorded and returned with `applied_to_weights=false`; no weights, topology or hidden reward current changes. Reviewed future plasticity rules belong in `scripts/body_plasticity.py` and must be explicitly registered.
- Racing embeds the same complete `BrainView` in an independent right-side `BrainMonitor`, with the original region palette, FLY2 counts, neuron selection and optional official skeletons. It renders on demand at browser refresh cadence during interaction, caps pixel ratio at 1.25, and closes its subscription when collapsed, offscreen or hidden. No second native brain is created.
- The default `observe` session is asynchronous: race physics runs at 1/60 s independently of CPU neural latency. It samples only the latest real camera with WebGL2 asynchronous pixel readback, keeps at most one native request in flight, and accumulates rewards plus short nitro/touch signals. `observation.context` records source-world time and the signal interval without affecting neural inputs. The UI shows sample time and age. Selecting another observed car releases/reinitializes the session without stopping normal racing. `drive` remains an explicit 100 ms lockstep native experiment; do not describe it as wall-clock real-time.
- Per the user's requested feedback, positive named rewards are explicitly converted to `observation.sugar=true` in the next neural observation window. Asynchronous observation can aggregate multiple world events; it never advances or rewinds the game. The reward endpoint itself remains frozen and never injects current. Sensory definitions are in `web/src/race/sensory.ts`; `docs/body-api.md` is authoritative. Performance evidence in `reports/racing-stutter-before.json`, `reports/racing-stutter-after.json` and `reports/racing-performance-fix.md` supersedes prior claims based only on draw FPS.
