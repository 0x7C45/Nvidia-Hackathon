# 赛车卡顿修复

2026-09-13。本机浏览器实测 GPU 为 `ANGLE Metal Renderer: Apple M4`，WebGL 2.0，已启用硬件加速。前端使用 TypeScript / Three.js；完整神经模型通过 Python 服务调用原生 C++，神经计算运行在 CPU 上。

## 根因

旧版把随车观察和原生驾驶都放进同一分支：`await body.step()` 后才推进世界 100 ms。较活跃的完整模型每次计算约需半秒或更久，所以浏览器正常刷新时，绝大多数帧只是重画同一车辆位置。

旧版还在 `requestAnimationFrame` 之上叠加 61 FPS 的时间阈值。实际回调间隔有轻微波动，部分正常帧被错误跳过。此外，相机使用同步 `readRenderTargetPixels`，脑视图拖动被限到 30 FPS。

以前的协议／数值测试证明了真实数据和固定权重，但没有证明车辆运动流畅。本次补充直接测量世界推进和停顿时长。

## 本机前后对照

相同浏览器窗口（842×837）、跟车镜头、4 果蝇加机械对手、同一个第 36 代控制网络、完整脑观察开启。各采样约 8 秒，逐个动画回调读取实际世界时钟，使用同一测量方法。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 墙钟采样时间 | 8.0143 s | 8.0147 s |
| 世界推进时间 | 1.6000 s | 8.0167 s |
| 世界／墙钟倍率 | 0.200× | 1.000× |
| 浏览器动画回调 | 481 | 481 |
| 世界位置发生更新的回调 | 16 | 481 |
| 实际赛车绘制帧 | 392 | 481 |
| 最长世界停住的时间 | 533.3 ms | 17.7 ms |
| 动画回调间隔 P95 | 17.6 ms | 17.7 ms |
| 同期真实神经步骤 | 16 | 11 |

证据为 `racing-stutter-before.json`、`racing-stutter-after.json`。两次测量中浏览器都接近 60 次回调／秒；问题主要是世界没有移动。修复后每个被测回调都有世界更新，同时原生脑仍在实际计算，未关闭神经模拟、替换神经数据或改动图规模。

修复后样本仍包含 166,700 个神经元、3 批官方外形网格，显示数组为 23,495 个活跃神经元与 173,117 次脉冲，与对应原生 step 一致。由于采样输入时刻不同，两个运行的神经活动无需相同。

## 实现

- 默认随车观察与世界时钟解耦：世界固定 1/60 秒推进，后台最多一个采样／神经请求；空闲后取最新图像，不排队。
- 相机与预览改成独立的 WebGL2 异步像素缓冲，GPU fence 完成后读取小块数据，避免同步读回阻塞帧循环。
- 移除赛车的额外帧率阈值，脑视图拖动也跟随浏览器刷新。暂停或离屏时保留按需绘制。
- 积累原生请求等待期间的奖励，确认前固定奖励截至位置，避免重发或吞掉后续事件；短暂氮气和触碰信号保留到下一次观察。
- 用 `observation.context` 记录采样世界时间、感觉区间和来源。该字段仅作记录，数值测试确认它不改变神经输出或神经时间。界面显示采样赛时、结果年龄和实际耗时。
- 原生驾驶保留严格 100 ms 锁步实验；它的速度仍受真实 CPU 神经计算限制。它与默认实时观察在界面上明确区分。

## 验证

JavaScript 20 项、Python 38 项，共 58 项通过。新增检查覆盖：在原生响应未完成时游戏仍可持续推进；观察不会调用世界步进；旧图像不排队；奖励及短暂感觉信号保留；最后奖励刺激不会增加已完成比赛的时间；时间戳不会改变神经状态。日志在 `racing-async-js-tests.log`、`racing-async-python-tests.log`。

TypeScript 检查、生产构建、Ruff、Black 及相关 Python 模块严格 Mypy 通过。实际浏览器未发现脚本或图形错误。上述为本机短时测量，不把神经模型本身描述为已经达到实时计算速度。

随后完整跑完一场 3 圈比赛（46.05 个游戏秒），后台记录了 99 次真实神经观察。启动连接期间切换到果蝇 03 后，最终观察源正确绑定到该车；异步车载预览产生有效像素，采样记录的奖励总和与服务回执一致，见 `racing-async-runtime.json`。结束比赛时额外刷新状态栏，避免留下旧的暂停按钮与未冲线排名。
